# 原生界面操作与问题恢复

以下为2026-10-08 Microsoft Edge实测行为，仅在当前界面匹配时使用。不复制历史坐标或元素ID。

## 输入和异步状态

- 每轮动作后读取最新AX；页面重建会使旧ID失效。异步加载期间字段可能暂缺，等实际字段出现后再操作。
- 点击无反应先看最新状态与截图，区分聚焦、屏外、弹层已开和处理中，不盲目连点切换控件。
- 一般文本框可用setValue，但显示值不证明业务状态更新。价格输入可实际聚焦、全选、输入、失焦，再读回SKU。曾出现批量栏199而SKU仍0，该情况未解决前不可称已配置价格。
- 刚重开编辑页可能短暂显示不完整图片分组，等异步数据稳定后判断，避免误删。

## 文件选择器

1. 在正确上传区域选本地上传，部分入口直接弹选择器。
2. Command+Shift+G前往完整文件或目录路径，使用当前路径文本框。
3. 单文件核对选中文件名与路径再打开。
4. 多文件先选首张，Shift+Down扩选到末张。实测Command+A未可靠全选，连续扩选可见“20个项目20份文稿”。核对总数再打开。
5. 回网页核对上传完成、张数、缩略图。选中状态不是上传完成。

## 轮播图绑定和首图

曾因先上传图再完善规格，出现“所有轮播图必须绑定规格”，即使表面已在银色组。优先先建立银色款式，再直接向银色组上传，白底第一。

错误重现先检查实际分组及未绑定图片，只修正明确问题图，不删除整组或重复上传：

- 已验证修复：删除问题白底图，从正确银色组重传同一白底图。
- 重传在末尾时，用悬停出现的设置首图控件。实测设为规格首图后白底自动到第一位、SKU图更新，最终核验规格首图/正面白底图标识和错误消失。
- 移动至同组的选项灰置不能证明内部绑定正确；拖动尝试不能代替实际顺序核验。

## 保存

保存草稿曾出现“草稿编辑成功”，随后通用结果页写“提交成功，预计5工作日”，但列表仍草稿。必须读回准确货号状态。

点击保存后页面不变且还有必填错误，不记录成功。保留表单，记录未完成字段与未确认保存状态，补齐后重试。不得因保存不生效而改点提交审核。
