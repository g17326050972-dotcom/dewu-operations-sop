# 得物商家货品池编码

把已上架商品各礼盒规格的「商品编码」维护为用户约定的货号编码。复用已登录的得物商家后台，仅处理本次指定或刚完成上架的货号。保存草稿、提交审核不等于上架；如果商品尚未可在货品池添加，记录待办，后续可用时再补。

## 输入与编码规则

输入是一个或多个完整货号，以及当次需要处理的商品范围。货号从用户指定资料、上架进度或对应商品获取，再与「编辑SKU」窗口顶部的实际货号核对。录制示范的货号是变量，不能写死或沿用上一款剪贴板内容。

| 实际礼盒规格 | 商品编码 | 以货号 YX9639002 为例 |
| --- | --- | --- |
| 品牌礼盒 | 货号原文 | YX9639002 |
| 炽热挚爱 | 货号直接拼接大写 B | YX9639002B |
| 钟意一生 | 货号直接拼接大写 A | YX9639002A |

「货号+B/A」表示字符串拼接，不输入加号、空格或分隔符。保留完整货号，不自行删减或改写其内容。只处理实际存在的规格；只有品牌礼盒时只填该行，不为补齐编码创建新规格。按礼盒名称定位行，不依赖行号、颜色、尺码或 SKU_ID 的顺序。其他礼盒名称或无法区分的多行规格先保留并报告，不自行发明后缀。

## 工具与入口

先检查可用工具；有能核对 SPU/SKU 并维护该字段的专用连接器时优先使用。否则用 **Computer Use** 操作已登录浏览器。本流程录制于 Microsoft Edge，入口为「商品 → 商品管理 → 商家货品池」，页面路径 `https://stark.dewu.com/main/skuNo`。依据实时页面文字、输入框、表格行和窗口定位，不回放旧坐标、旧元素 ID 或会话参数，不凭录制内容猜测私有 API。

## 批量表格方式

多款编码维护优先检查实时页面的「批量编辑sku」或对应导出/导入入口，采用用户指定的「导出 → 填码 → 导入 → 再导出核验」。先按下节第1–2步定位目标商品并确认入池，再取后台当前导出表或专用编辑模板。该表格方式由用户明确提供，模板及具体导入控件尚未实测；只采用当前页面实际支持的格式，不能把商品搜索窗口的「导出商品」误当作一定包含可导入SKU编码的模板。

读取导出表头和导入说明，按完整货号、SPU/SKU ID及礼盒规格精确匹配目标行，仅改「商品编码」列，其余数据保留。编码和ID按文本处理，避免丢失前导零或变成科学计数法。使用适用的电子表格技能处理文件；不要另造未获后台支持的模板。导入后核对成功/失败行数；再从后台重新导出同一范围，以唯一SKU标识、货号、规格和商品编码逐行比对，覆盖全部目标行。不能用本地上传文件或旧导出文件代替后台读回。模板不支持该字段、行身份不明确或导入报错时，说明具体问题并改用下节逐款方式完成可处理部分。

## 界面逐款方式

1. **先查货品池。** 若「商品货号」框不可输入，先点击「商品品牌」已有值右侧的×清除品牌，确认货号框恢复可用；「重置」可能仍保留品牌，不能替代清除。再输入目标完整货号，点击「查询」（可能显示为「查 询」），核对结果货号、品牌、商品及 SPU ID。多货号用英文逗号分隔，按页面当前数量限制查询；不要混入中文逗号或沿用旧筛选内容。
2. **缺失时添加商品。** 页面提示「维护商品编码时，请务必先导入商品至货品池，再维护商品编码」。仅在准确查询确认缺失时，使用「添加商品 → 通过搜索添加商品」，按「商品货号 / 请输入商品货号」查询；已实测此窗口也支持英文逗号分隔多个货号。核对每行货号、品牌和SPU ID；结果全部是当次目标时勾选表头全选框，否则逐行选择目标。必须看到「已选择N项」且数量正确，再点「确定」。等待加载完成，必要时关闭搜索窗口回货品池重新查询，看到准确目标行才继续。单纯查出商品或点未启用的确定都不算添加；查询新货号可能清空旧勾选。已存在则直接编辑；搜不到不重复添加其他相似款。
3. **打开对应行的「编辑SKU」。** 将窗口顶部「货号」和 SPU ID 与目标行核对；有多个结果时不可点击未限定商品行的第一个编辑链接。切换下一款后重新读取货号并生成整组三种编码，不能复用上一款编码。
4. **填各规格的「商品编码」。** 在对应礼盒行的「商品编码 / 请输入商品编码」输入框全选替换为规则生成的值，失焦后读回。避免误填相邻「辅助商品编码」或筛选区「商品编码」。只修改本次编码字段，不改得物码、库存、成本或出价。已正确的值可跳过；明确要求按该规则维护的目标商品如有错误编码，按规则修正。
5. **核对并保存。** 保存前检查窗口货号、每行规格与完整编码、末尾 A/B、大写和空白字符。点窗口内「保存」（可能显示为「保 存」），等待「保存成功」或明确错误。结果不明时先重新查询读回，避免盲目重复保存；确认同一失败重复出现后记录具体原因，继续其他可完成货号。
6. **重新打开验证持久化。** 关闭编辑窗口，在同一目标商品行再次打开「编辑SKU」，核对窗口货号及所有目标礼盒行编码。只看到输入值或成功提示，尚未完成重开读回时，报告「已填写 / 已提示保存成功，待读回」，不能报告「全部核验完成」。

## 衔接与交付

新品上架任务包含维护货品池编码时，把本步骤作为上架后的收尾项。用户明确只保存草稿时不触发。既有登录状态不足时让用户完成登录后续做，不获取或记录凭据。

报告已保存并读回的货号与各规格编码、未上架/暂不可添加的货号、未知规格或失败原因。区分商品上架状态与编码保存状态；不因编码保存成功而推断审核通过或商品新上架。

需要检查示范与实测边界时读 [录制依据](references/recording-evidence.md)。技能结构校验不等于自动回放通过。
