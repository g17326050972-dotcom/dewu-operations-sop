# 得物出价与自建折扣

优先确认或复用新品上架时已经填写的预出价，按货盘折扣加入现有自建活动；用户明确要求出价且缺少已有出价时，按其授权和已核实规格处理。折扣完成后检查到手价尾数并回读生效结果。

## 使用范围与输入

- 按当次任务指定的货号、SPU 和销售规格操作，核对实际可出价及报名资格；不能把列表中顺带出现的其他商品或礼盒加入范围。已有明确的编码完成记录时直接使用，不重复逐款打开编码页；用户直接要求出价/折扣时，仅在本次后台操作确实依赖编码或身份不清时补查。编码成功不能代替可售或可报名资格。
- 所需输入为目标货号、需要确认的礼盒/尺寸/渠道，以及货盘来源。当次用户若提供明确预出价清单，按该清单核对。
- 业务确认、活动提交和尾价修正分别遵循当次用户授权。录制学习只授权学习；当次任务已经明确授权相应操作时，完成核对后继续，不重复索要确认。历史示例商品不能自动纳入本次调价范围。
- 历史示例、价格显示差异和证据边界见 [references/recording-evidence.md](references/recording-evidence.md)。遇到示例值、旧新增出价路径或价格差异时再读。

## 读取货盘与价格核对

默认货盘是 `/Users/nan/Desktop/戴拉银饰货盘.xlsx` 的 `Sheet1`，以 **B 列货号**精确匹配；D 列为品牌礼盒原价参考，E 列为需要核对单位的折扣值，F 列为目标到手价依据。每次执行都读取当前文件，历史行号不能代替查找。只读打开，不改动原表。

逐款读取 E 列并结合文本、单元格格式和列单位归一为折扣率 `r`：`8`或`8折`表示0.8；明确比例值0.8表示0.8；Excel真实百分比底层0.8、显示80%时也是0.8；文本`80%`需除以100。E缺失、含义不明或不满足`0<r<=1`时先核实，不能重复除以10。后台“折”输入框填写归一后的`r×10`，不是直接照抄比例或百分比底层值。不能把示例8折作为全部新品默认值。

预出价来源与最新整数期望：

- 品牌礼盒：D列是原价参考，目标到手价`T=F`。
- 钟意一生、炽热挚爱礼盒：目标到手价`T=F+30`，仍需核对当前完整规格名称；旧规则的原价参考是`T/r`。
- 对明确的正整数T，以Decimal计算最新整数期望`B=floor(T/r)`，并验证`ceil(B×r)=T`。不把D的显示舍入值当作唯一合法价格。

先记录货盘底层数值、显示值与后台现值。确认阶段允许既有旧显示预出价，以及按最新公式核验的整数预出价：例如D=198.75显示199、T=159、r=0.8时，旧价199可先确认后按授权修尾价，新预填198也正确，不能误报为偏离货盘。对旧参考除法/显示值与最新整数B，逐行记录可解释来源；实质偏离当次明确清单及这些已核实来源时再报告差异。确认阶段不重复新增或擅自改预出价，折扣后的尾价修正单独执行，不能把所有商品统一减1。

货号匹配不唯一或目标来源含义不清时，先保留已核实部分，询问影响当前操作的最小缺口。

## 确认已有预出价

1. 优先检查是否有适用的得物专用连接器；没有时使用 Computer Use 操作已登录后台。按实时文字、表格和商品身份定位，不能回放旧屏幕坐标或调用后台私有 API。
2. 进入“商品 → 价格风险预警”，按目标货号查询待确认的原有预出价。逐行核对货号/SPU、礼盒/尺寸、渠道、价格、数量与状态，避免同货号的其他规格被误选。
3. 确认本次确有待生效/待确认预出价。已生效的无需重复确认。任务仅为“确认已有预出价”时，未找到则报告缺项；用户明确要求“出价并配置折扣”时，先确认确实不存在已有出价，再按最新货盘、实际规格、可出价资格和有依据的库存处理新增。库存缺乏依据时报告缺口，不套用历史默认1。
4. 将后台现值与当次清单或前述可解释的预出价来源核对。旧显示预出价与最新整数期望B均须按实际来源判断；例如199与198不能仅因D显示199就判198错误。实质偏离已核实来源、规格或渠道不符时报告差异，先解决该差异；不得为了套用历史示例改预出价。数量读取实际预出价，不把演示中的1设为通用默认。
5. 在当次授权范围内勾选目标记录，按当前页面执行“批量确认”→“确认出价”等实际确认操作。等待结果后，用同样货号和筛选条件重新查询；核对目标不再处于待生效/待确认列表。仅点击按钮不能记为成功。

## 追加到自建折扣活动

1. 进入“活动 → 自建活动 → 营销工具 → 营销工作台”。定位**当前进行中**、适合银饰及本次渠道的折扣活动，核对名称、有效期、渠道与状态。续期后的活动 ID 会变；不要固定示例 ID。没有合适活动或有多个无法区分的活动时，说明具体缺口，不自行新建或改续期设置。
2. 打开活动详情，先按目标货号检查已报名情况。已存在且规则正确的商品直接核验；发现重复或规则不同，先核对当次任务是否包含编辑，避免重复追加。
3. 点击“追加商品”进入添加流程，按下列模式在线选品或使用官方模板批量导入。逐款采用货盘 **E 列归一后的折扣**，折扣对应库存保持已演示的**不限制**；若当次用户另有库存限制，按其任务执行。先完成折扣并读取实际到手价，再按后文修正需要调整的出价；不能改折扣来凑目标尾数。
4. 添加后检查待提交清单中的完整目标、数量、最低出价、折扣、到手价和库存规则，再“下一步”。检查资损风险、并行活动及折后价；若出现未预期的风险或叠加结果，先报告具体风险。对已核实且获当次授权的商品执行“确认无风险，提交”。
5. 进入活动详情，按货号逐款查询，回读**审核状态、最低出价、折扣、到手价、折扣对应库存、购买渠道、并行活动**。审核中或驳回按实际状态报告，不能统称审核通过；预览值不能代替提交后的列表值。

### 在线选品（已实测）

点击“在线选品”，输入货号后按 Return 选定匹配候选，看到完整商品项再点“查询”；仅点击候选文本可能未选中并导致空查询。用结果中的货号和 SPU 核实身份，逐款将E列归一后以折数`r×10`填入并等待到手价稳定。

勾选目标，确认“添加（N）”数量再添加。添加一个商品后，弹窗可能仍在原处并重置；商品已进入下方待提交清单时，可以直接输入下一货号继续。不能仅因弹窗未关闭就重复添加；最后核对下方清单包含完整目标且无重复。

### Excel批量报名（多款优先，已实测）

多款默认优先从当前追加商品页选择“通过Excel导入商品”，不要仅因只有4款就改成逐款弹窗报名。先下载**本次页面提供的官方模板**，检查表头、说明、必填字段和可填写规则。2026-10-14实测的“按照SPU维度设置折扣”模板只需填SPU ID、折扣、库存，商品名称及货号留空，由平台补全；该模板库存`-1`表示不限制。只在当前模板说明仍相同时沿用这些字段与取值；模板变化时按当前说明处理。按完整货号/SPU映射目标，逐款将货盘E列归一后按模板实际单位填入折扣，保留商品ID完整性。

导入后先读取成功/失败反馈和待提交清单，核对目标数、身份、折扣、最低出价、到手价、库存及重复项；只对成功且读回一致的记录进入风险校验和提交。模板不支持所需规则、导入失败或读回不清晰时，保留具体错误并改用已验证的在线选品；不要混入未知或部分成功的重复记录。

2026-10-14已完成4款一次导入、提交与审核通过回读，具体证据及模板字段见 [references/bulk-enrollment-20261014.md](references/bulk-enrollment-20261014.md)。历史通过不代替本次核验；已报名且正确的商品直接保留，不为重演批量流程删除原报名。

## 折扣后检查并按授权修正9尾价

用户确认的平台计算规则为：含小数的折后金额向上取整，`到手价 = ceil(整数出价 × 折扣率)`。以最终详情为实际结果，不能用表格显示四舍五入代替平台价格。

1. 只检查**本次指定商品和规格**的已生效出价与活动价。到手价已是9尾且符合明确目标时保留；已是9尾但与目标不符时报告差异，不能为了统一规则降价。范围外的录制示例不追改。
2. 明确目标整数到手价 `T`：品牌礼盒通常为货盘F，钟意一生、炽热挚爱通常为 `F+30`；当次用户明确指定目标时以其目标为准。确认当前出价来源，并按前文读取E列单位归一得到`r`。T/E未知、T不是明确正整数或并行活动使实际价格偏离本规则时，报告实值与缺口，不猜一个9尾目标。若本次要求9尾而来源T不是9尾，报告目标冲突，不擅自选最近9尾；当次用户明确指定非9尾目标时按该指令。
3. 用 **Decimal** 从字符串读取T、E和当前出价，先计算当前价及“当前出价−1”的 `ceil(B×r)`。当前任务只授权降1时，仅在降1能达到T时执行；不能一律减1。需要推导整数出价候选时，取 `B=floor(T/r)`，并核验 `ceil(B×r)=T`，其中 `0<r<=1`。更大降价或涨价须在当次授权范围内。
4. 纯计算可运行 `python3 scripts/price_for_takehome.py --target 159 --discount 8 --current 199`。脚本的`--discount`仅接收**折数**，先把归一r转换为`r×10`传入；例如源表比例0.8或80%均传8，不能直接传0.8。脚本不操作后台；输出当前价、降1结果、计算候选及校验。例：199×0.8=159.2→160，需要198×0.8=158.4→159；211×0.8=168.8→169已经满足，应保留211。
5. 对已授权且确需调整的目标，在“出价管理/调价工作台”等当前可用入口定位**对应已存在出价和规格**，仅改已计算核实的出价；保留非本次修改的渠道、数量、库存与折扣。实测入口为“出价管理”按完整货号查询唯一商品→“编辑”→原有“品牌直发”分组→目标礼盒/尺寸/颜色行（本次为“品牌礼盒-F-银色”），编辑“我的出价”，按当次要求选择生效时间。数字框使用 `typeText` 键入数值后按 Tab，触发更新并读回；粘贴曾导致归0，输入后必须核对字段值和行内库存，错误值不可提交。
   核对原有渠道、库存及生效设置后提交调价。出现参与折扣活动的提醒时，核对活动身份和受影响规则，再在已有授权范围内“确认出价”。关闭编辑，重新按完整货号查询，读取现价、售卖/生效状态和库存；不能用编辑框中的值代替保存后的结果。
6. 重新查询生效出价，再回到活动详情查询该货号，核验实际最低出价、折扣、到手价、库存规则和状态。不能把已填写、调价待生效或预览价格报告为修正完成。若页面实际价与计算不符，停止该条并报告，不连续试价。

## 完成记录与停止条件

按商品/规格记录：货号、SPU、确认前后状态、原有预出价、E 列折扣、目标与最终到手价、如有调价则记录前后出价及生效状态、库存规则、渠道、活动名称/ID、审核状态及差异。分别说明“预出价已确认”“折扣已提交/审核通过”和“尾价已修正”的实际完成范围；只读核验、填写、提交和审核通过不得混用。

确认或提交反馈不明时，先重新查询结果；仍无法判定就保留待核验状态并停止该条，不重复提交。凭据、验证码和用户未授权的新建活动、改价或改库存决定交由用户处理，其他独立且已授权的目标可继续核验。
